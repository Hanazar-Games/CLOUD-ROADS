# 开发记录

## Phase 0 — 完成

完成 Vite + TypeScript 项目、Three.js 场景与透视相机、基础光照、天空色、游戏循环、窗口缩放、输入管理、开发者飞行相机与 F3 调试界面。

文件范围：项目配置、`index.html`、`src/main.ts`、`src/style.css`、`src/game/`、`src/camera/`、`src/input/`、`src/debug/` 和基础测试。

验证：build、lint、游戏循环测试和实际浏览器渲染／操作测试均通过。Phase 0 的临时平面在 Phase 1 被流式地形替换。

## Phase 1 — 完成

文件范围：`src/world/`、`src/terrain/`、游戏集成、地形／生命周期／长距离模拟测试及浏览器测试。

职责分配：

| 模块 | 职责 |
| --- | --- |
| WorldSeed / Noise / HeightFunction | 不依赖渲染器的确定性世界采样 |
| TerrainGenerator / TerrainTopology | 属性生成与 LOD 公共边界连接 |
| TerrainWorker / TerrainWorkers | 有限并行任务、数据转移、超时及错误反馈 |
| ChunkPlanner / ChunkManager | 空间覆盖、优先级、过期结果丢弃、LOD 替换与网格池 |
| TerrainChunk | 复用几何、更新 GPU 属性和包围球 |
| World / FloatingOrigin | 种子世界生命周期、逻辑坐标和渲染坐标分离 |

测试覆盖：

- 同种子同坐标高度一致，异种子产生不同地形。
- 正负世界坐标、相邻边界的高度／法线／颜色一致。
- 64 / 16 / 8 格的跨 LOD 边界一致；三角形朝向与总覆盖面积正确。
- 10 / 30 / 100 公里模拟中的有限数值、有限活动范围和原点重定位。
- 远距离瞬移后丢弃旧任务、卸载后复用几何、世界销毁后忽略迟到结果。
- Worker 失败时显示错误并停止继续调度，可重新加载种子恢复。
- 生产构建中实际飞行超过 30 公里，至少五次原点重定位；停下后恢复 289 分块。
- 种子往返切换后恢复相同起点，旧世界的网格和 Worker 被释放。

Phase 1 验收结果：20 项单元测试、3 项 Playwright 端到端测试通过，TypeScript build 和 ESLint 通过。

性能抽测：本机 Apple M5 Pro、Chromium / ANGLE Metal、1920×1080，默认种子静止观察约 60 FPS、99 次 draw call；以 120 m/s 连续飞行 10 秒，平均 60 FPS，最大帧间隔约 16.8 ms，没有记录到超过 50 ms 的主线程任务。这是单机短时抽测，不代表所有硬件。`npm run benchmark` 可复测连续飞行。SwiftShader 软件渲染明显较慢。

## Phase 2 — 完成

新增 `RoadGenerator`、`RoadSegment`、`RoadSpine`、`RoadDebug`，接入 World、自由相机、道路观察按钮和 F3 道路指标。

候选路线同时评价地形落差、坡度、转弯、悬崖和种子生成的方向引导。相邻控制点使用显式端点切向量的三次 Hermite 样条；位置和切线连续，避免未经约束的插值超调。弧长表用于道路里程采样，生成结果不依赖帧率或每帧批量大小。

当前采用向北单调前进的走廊，直接排除自交。普通坡度目标 ±6%，每段端点坡度变化不超过 2%；转向每段最多 18°。10 / 30 / 100 公里自动测试逐段检查曲线内部采样点的坡度 ≤10%、半径 ≥100 m、连续性及有限数值。

生成窗口预留前方约 2300 m、后方约 1600 m（南北投影），最多驻留 96 段。远距离返回已释放区域时，从种子起点以每帧预算分批重建，不永久保留完整路线。

Phase 2 验收：build、lint、26 项单元测试和 4 项 Playwright 测试通过；已在实际场景检查中心线与控制点。

## Phase 3 — 完成

新增 `RoadMesh`、`RoadMaterial` 与网格测试。路面为 8 m 沥青，两侧各 1.2 m 路肩；原创 GLSL 绘制中心虚线和边线，保留 Three.js 的光照、雾和色彩转换。横坡抬高弯道外侧，控制点之间连续过渡。

道路网格与骨架共用样条采样缓存，每段 24 个间隔；只在窗口变化时更新预分配的顶点、法线和 UV 缓冲。路面只增加一次 draw call；浮动原点仅更新对象平移。UV 使用附近的 12 m 标线周期原点，避免长期累计里程降低标线精度。

验收覆盖网格宽度、三角形朝向、横坡方向、UV 连续性、缓冲复用、重定位与释放。生产浏览器新增向北飞行超过 30 公里的道路流式生成测试，并验证返回后重建、种子切换与 shader 无错误。

Phase 3 最终验收：build、lint、29 项单元测试、5 项 Playwright 测试全部通过。相同 M5 Pro / Metal / 1080p 环境下向前飞行 10 秒，道路窗口从 25 段扩展至 38 段，约 60 FPS、最大帧间隔约 16.8 ms，没有记录到超过 50 ms 的主线程任务。该短时结果不代表所有硬件或长期运行表现。

## Phase 4 — 完成

新增 `RoadFrame` 与 `RoadCorridor`，调整 `TerrainGenerator`、Worker 数据协议、`TerrainTopology`、`TerrainChunk`、`ChunkManager` 和 `World`。路面与地形共用道路横坡坐标系；道路中心两侧 12 m 路基位于路面下方约 0.08 m，向外按自然地形高差平滑切坡或填方，最大影响半径 160 m。

道路窗口扩大为前后各约 2600 m（南北投影），最多保留 96 段。覆盖就绪后，按道路版本缓存走廊，并给每个 Worker 任务发送局部快照，避免先生成未耦合地形。当前走廊查询依赖路线向北单调前进；下一阶段加入发卡弯时需要同步调整空间查询。

所有 LOD 的公共边界改为 4 m 间隔，粗网格内部通过环带三角形连接细边界；沿道路分块提升为 64 格，保证路基精度。测试检查跨分块／LOD 的高度、法线、颜色，以及三角形面积、朝向和边的连接次数。

新增切坡、填方、横坡、局部快照复现与生成顺序测试。两个种子的实际路面和地形网格使用 Three.js Raycaster 检查中心及两侧路肩，测试采样处间距均在 0.01–0.2 m。浏览器验证沿路 LOD 提升、30 公里飞行、重定位、返回起点和种子切换；已目视检查连续路基。

Phase 4 验收：TypeScript / Vite build、ESLint、34 项单元测试与 5 项 Playwright 测试全部通过。Apple M5 Pro / ANGLE Metal / 1920×1080 向前飞行 10 秒约 60 FPS，p95 帧间隔 16.7 ms、最大 16.8 ms，没有记录到超过 50 ms 的主线程任务。结束时活动分块 289 个、LOD 分布 36 / 50 / 203、94 次 draw call、约 19.6 万三角形。这是单机短时抽测，不代表所有硬件或长期运行表现。

## Phase 5 — 完成

调整 `RoadGenerator`、`RoadSegment`、`RoadSpine`、`RoadCorridor` 与 World 集成，新增 `RoadIndex`。普通候选路线仍使用地形评分；当地形高差超过阈值时，进入确定性的山路序列：渐变转向、横向爬升／下降、150° 折返弯、横向连接段、反向折返弯、退出。弯心最小半径约 36.7 m，弯间连接段至少 384 m，每组结束后至少间隔 4 km 才能触发下一组。坡度限制为 ±6%，规划状态随控制点保留，增量生成和重放结果一致。

道路改为按水平弧长积分平滑方向与坡度，端点曲率及竖向坡度变化率归零，消除旧三次 Hermite 路段的曲率跳变。横坡随实际曲率变化，上限 6°。每段使用 48 个采样间隔，普通路段长 96 m、发卡弯长 144 m；最多驻留 160 段，为折返增加的里程留出有界容量。

二维包围盒树用于最近路段查询和走廊裁剪，替换依赖 Z 单调性的二分查询；Worker 接收独立线段，裁剪后不会错误连接分离的路段。当前生成器仍保持北向推进，索引已覆盖反向道路。道路视角和里程改用水平距离最近的路段，新增「发卡弯视角」及 F3 发卡弯数量；俯瞰相机按耦合地形抬高并指向弯心。

修复回退时地形覆盖不足的问题：即使相机还在已保留的路线内，也会检查后方 2600 m 走廊并按需重放，避免新加载地形缺少道路数据。

测试按 TDD 加入曲率／横坡连续、上坡与下坡折返、弯间净距、反向走廊、空间索引与穷举结果一致、回退覆盖和俯瞰相机避开山体。真实路面／地形射线检查扩展到整个驻留窗口，包含急弯与两侧路肩。10 / 30 / 100 公里道路模拟、种子复现、有界内存和浏览器长距离飞行继续通过。

Phase 5 最终验收：TypeScript / Vite build、ESLint、43 项单元测试和 6 项 Playwright 测试全部通过；已在浏览器目视检查连续的两级折返路线及观察相机位置。

性能抽测：Apple M5 Pro / ANGLE Metal / 1920×1080 连续飞行 10 秒约 60 FPS，p95 帧间隔 16.7 ms、最大 16.8 ms，无超过 50 ms 的主线程任务；结束时活动分块 289 个、LOD 分布 40 / 49 / 200、96 次 draw call、约 21.6 万三角形。这是单机短时抽测，软件渲染浏览器的帧率不具代表性。

## Phase 6 — 完成

新增 `src/bridge/BridgeDetector.ts`、`BridgeMesh.ts`，接入 `World`、`RoadCorridor`、流式道路窗口和观察界面。先完成检测、谷地保留、几何支撑和生命周期测试，再实现桥梁生成。

检测使用自然地形：道路高出谷底 40 m 的连续距离至少 80 m、两端路面与自然地面的高差不大于 12 m、总桥段长度不超过 1400 m；桥跨内部还检查两侧净空，避免桥面穿入山体。缺少另一端落点、过长、浅谷和短沟不生成桥梁。高度采样只缓存当前道路窗口，随卸载删除。

道路前后预留范围扩大为 4000 m（南北投影），最大驻留 256 段，包含地形窗口、走廊影响范围与完整桥梁的检测距离。桥梁判定完成后才把带地基权重的局部线段快照送入 Worker。桥跨内部保留自然谷地，桥头 32 m 范围平滑接回原有切填方；100 公里模拟验证移动窗口内的判定和地形一致性。

路面继续复用原有沥青网格，桥面下方增加 2 m 厚混凝土底梁与两侧护栏。桥墩约每 32 m 设置一次，两端增加桥台，基础同时参考自然地形与耦合地形并埋入地下。桥面／护栏和支撑结构各使用一个固定容量的 `InstancedMesh`，共增加最多两次 draw call；坐标重定位只平移两个网格，流式更新复用实例缓冲，换种子和销毁时释放共享资源。

新增「桥梁视角」及 F3 桥梁／支撑数量。道路仍在生成时保留上一批桥梁，避免桥梁闪断；加载提示区分路线生成与地形加载，观察按钮等路线就绪后启用。

测试包括合成深谷的正反例、桥侧侵入拒绝、100 公里判定稳定与缓存上限、桥头过渡、局部 Worker 快照复现、实际曲线桥面的射线间距、桥墩基础、缓冲复用、浮动原点与资源释放。两个种子的射线检查验证混凝土顶面位于沥青下方、桥下地形与自然高度相符；浏览器覆盖桥梁观察、30 公里往返和换种子后恢复同样桥梁。

Phase 6 最终验收：TypeScript / Vite build、ESLint、52 项单元测试及 7 项 Playwright 测试全部通过；已在浏览器检查桥面、护栏、桥墩与保留的谷地。

性能脚本先等待路线就绪及地形加载完成，再测量飞行。Apple M5 Pro / ANGLE Metal / 1920×1080 连续飞行 10 秒约 60 FPS，p95 帧间隔 16.7 ms、最大 16.8 ms，无超过 50 ms 的主线程任务。末帧活动分块 289 个、97 次 draw call、约 25.2 万三角形，驻留 3 段桥梁、74 个支撑（含桥台）。这是单机短时抽测，不代表所有硬件或长期运行表现。

## Phase 7 — 完成

新增 `src/biome/BiomeSystem.ts`，使用独立种子噪声与逻辑世界坐标采样温度、湿度、雪线和地表颜色。海拔降低温度，局部气候改变森林过渡和雪线高度；山谷、森林、岩石、高山与雪区使用归一化的连续权重混色。雪线以 3000 m 为基准，叠加大范围气候与局部噪声，跨越 360 m 高度区间平滑积雪；陡坡减少积雪并露出岩石，避免水平白色条带和整面雪墙。

`TerrainGenerator` 删除原有简易颜色公式，在 Worker 内按道路耦合后的高度和法线采样地表。每个分块复用一个采样对象，继续写入原有颜色缓冲，不增加材质、网格或 draw call。世界地面查询与 Worker 使用相同算法，桥梁下方采样自然谷底，桥头与路肩采样耦合后的地面。

F3 新增地面生物群系、海拔、坡度、积雪覆盖、当地雪线、温度与湿度，每 150 ms 采样一次。只升降自由相机不会改变地面指标，底部海拔仍表示相机高度。界面阶段更新为 `/ 07`。

按 TDD 验证种子及采样顺序独立、海拔类型过渡、空间雪线、陡坡裸岩、权重归一化、颜色连续与复用对象。扩展跨 LOD 颜色接缝、耦合地形配色和 10 / 30 / 100 公里有限颜色检查；世界测试验证桥下地面与原点重定位后的采样一致，浏览器测试验证升降飞行和换种子复现。

Phase 7 验收：TypeScript / Vite build、ESLint、58 项单元测试及 8 项 Playwright 测试全部通过。Apple M5 Pro / ANGLE Metal / 1920×1080 连续飞行 10 秒约 60 FPS，p95 帧间隔 16.7 ms、最大 16.8 ms，无超过 50 ms 的主线程任务；末帧 289 个活动分块、97 次 draw call、251692 个三角形。这是单机短时抽测。

## 已知限制

- 未通过桥梁检测的深谷仍采用填方，可能形成较高、较陡的人工路基。桥梁目前只有基础混凝土高架，桥型与桥墩细节仍待丰富；悬索桥、斜拉桥和更长的地标桥尚未实现。
- 当前只有开发者自由相机；车辆、碰撞、云层、日落和植被尚未实现。生物群系目前通过地表顶点颜色表现，尚无树木、积雪几何或天气变化；温湿度是程序化气候参数，不是天气模拟。路线尚未由 Scenic Director 安排森林到雪山的体验顺序。
- 当前折返弯为受约束的 150° 弯道，路线仍向北推进；尚未生成跨越已有路线的 180° 回头路。山路序列形式和弯道半径的变化较少，后续可进一步丰富。
- F3 道路里程对应水平距离最近的路段，离开路线时不等于实际飞行距离；邻近不同路段的分界处可能切换定位。「道路视角」与「发卡弯视角」都是观察工具，不是自动驾驶。
- 后退到已释放的远处区域会从起点重放生成，距离越远等待越长；保持有界内存，重放期间道路视角按钮可能暂不可用。
- 远景通过基础雾隐藏；没有天空散射或真正云海。极高空或穿入山体的自由相机视角不代表后续驾驶体验。
- 超高速飞行或瞬移可以暂时超过生成队列吞吐，页面显示加载进度；旧 LOD 会保留到替换数据就绪。
- 每帧处理预算只能限制启动下一次几何更新，不能中断正在执行的单次更新。帧率目标仍需在不同硬件持续验证。
- 当前种子和地形算法仍在开发，后续算法调整可能改变同一种子生成的地形；不保留未发布版本的兼容层。
- Three.js 使初始 JS 构建超过 Vite 默认 500 kB 提示阈值（gzip 约 146 kB），构建成功。后续按实际加载需求优化拆包。
- 不包含运行时存档、移动端、控制器或 WebGL1 支持。
